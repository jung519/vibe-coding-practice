# B-12-O3 · O4 — 마무리 기록

> 관리번호: **B-12-O3**(흐름 한 문장) · **B-12-O4**(오류 점검표) · 작성일: 2026-07-21

## B-12-O3 — 흐름 한 문장

**"고객이 폼을 제출하면 서버(Supabase)가 예약을 저장하는 그 순간 트리거가 슬랙으로 알림을 쏘아, 사장은 아무것도 확인하러 가지 않아도 새 예약을 3초 안에 안다."**

## B-12-O4 — 오류 점검표 (오늘 실제로 만난 것들)

| # | 증상 | 원인 | 해결 | 교훈 |
|---|---|---|---|---|
| 1 | Zapier에서 Webhooks 트리거에 "프리미엄" 표시 | Webhooks by Zapier는 Professional 이상 전용 (교재 가정과 현행 정책 불일치) | 신규 계정은 14일 trial로 사용 가능 확인 | 도구 정책은 교재 시점과 다를 수 있다 — 공식 문서로 현재 정책 확인 |
| 2 | `ERROR: 3F000: schema "supabase_functions" does not exist` | Database Webhooks 기능을 켠 적 없어 스키마 미생성 | 웹훅 UI 대신 `pg_net` 확장 + 자체 트리거로 우회 (`create extension pg_net`) | 대시보드 마법 뒤의 실체(pg_net 트리거)를 알면 우회로가 생긴다 |
| 3 | 대시보드 Database 메뉴에 Webhooks 항목 없음 | 대시보드 개편 — Webhooks는 Integrations로 이동 | 스크린샷으로 실화면 확인 후 SQL-only 경로 채택 | 안내는 실제 화면 기준으로 — 메뉴 위치는 변한다 |
| 4 | Zap **Publish 불가** | 계정이 오리엔테이션 때 생성되어 trial 14일 경과 | **Supabase 직결(pg_net → Slack Incoming Webhook)로 전환** — 영구 무료 | 만료되는 인프라에 운영 알림을 얹지 않는다 |
| 5 | (예방) Slack에 `{"text": ...}` 형식 필요 | Incoming Webhook은 지정 스키마만 수신 — Supabase 표준 웹훅 페이로드 직송 불가 | 트리거 함수에서 `jsonb_build_object('text', ...)`로 본문 조립 | 직결 시 페이로드 변환 책임은 우리 쪽 |

### 비밀값 관리 (점검 완료)

| 값 | 위치 | 저장소 커밋 |
|---|---|---|
| Slack Incoming Webhook URL | DB 함수 안에만 | ❌ (setup.sql은 플레이스홀더) |
| Zapier Catch Hook URL | 폐기됨 (트리거 삭제) | ❌ |
| service_role key | 사용 안 함 | — |

### 남은 리스크 (수용 기록)

- pg_net 전송 실패 시 재시도 없음 → 실패 시 `net._http_response`에서 확인 가능. 카페 알림 수준에서 수용, 중요도 올라가면 Edge Function 전환.
- Slack Webhook URL 노출 시 스팸 가능 → 노출 시 Slack 앱에서 재발급 후 함수만 교체.
