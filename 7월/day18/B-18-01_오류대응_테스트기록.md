## ① 버그 사냥 — 일부러 이상하게 사용 (발견 6건)

Playwright 자동 공격 스크립트 + SQL 제약 실측으로 수행 (증거 전부 실측):

| # | 발견 | 우선순위(교재: 데이터>영어>화면>디자인) | 처리 |
|---|---|---|---|
| 1 | **orders 서버 무방비** — 직접 API로 음수 총액·비JSON items·아무 전화 형식 저장 가능 (check 0개) | 🔴 데이터 | ✅ check 6종 추가 |
| 2 | **과거 날짜 예약** — 직접 API로 어제 날짜 통과 | 🔴 데이터 | ✅ KST 기준 BEFORE 트리거 |
| 3 | **길이 무제한** — 이름 200자·요청 5,000자 저장됨 | 🟠 엣지(교재 ③) | ✅ maxlength 7필드 + 서버 check |
| 4 | **수량 무제한** — 담기 50연타 = 90만 원 주문 | 🟠 엣지 | ✅ 품목당 10개 + 한국어 안내 |
| 5 | **이메일 미검증** — "이건이메일이아님" 저장 | 🟡 형식 | ✅ 형식 검증(선택 필드) |

## ③④ 엣지 케이스·메시지 (전부 한국어, "무슨 일+어떻게")

- 빈 입력: 기존 처리 유지 ✓ / **길이 제한**: maxlength(이름 20·요청 200·이메일 60·주소 80) / **중복 제출**: 기존 가드 정상 확인
- 신규 안내문: "같은 상품은 한 번에 10개까지 주문할 수 있어요. 더 필요하시면 요청사항에 적어주세요." · "이메일 형식을 확인해주세요. (예: name@example.com)…"
- 영어 코드 노출: 화면 표시는 0건 (console.error만 원본 유지 — 교재 원칙)

## ⑥ 처리 전·후 비교 (실측 로그)

| 공격 | 처리 전 | 처리 후 (라이브 실증) |
|---|---|---|
| 이름 200자 | 200자 그대로 저장 | 클라 20자 컷 + 서버 400 (A2) |
| 요청 5,000자 | 저장됨 | 클라 200자 컷 + 서버 400 (A6) |
| 담기 50연타 | 90만 원 주문 가능 | 10개 상한 + 안내 (E3·E4) |
| 과거 날짜(직접 API) | 통과 | **400 PAST_DATE** (A1) |
| 음수 총액(직접 API) | 통과 | 400 check 위반 (A3) |
| items 쓰레기 문자열 | 통과 | 400 JSON 오류 (A4) |
| 전화 "abc" 주문 | 통과 | 400 check 위반 (A5) |
| **정상 데이터** | 통과 | **여전히 통과** ✅ (라이브 예약 '정상회귀' 접수 + 전 스위트 회귀) |

- 서버 공격 6종 **전부 거절** (쓰레기 행 0개 — 거절이라 오염 없음)
- 정상 회귀: 라이브 예약 1건 접수 + 회귀 스위트 5종(11/11·5/5·3/3·8/8·5/5) + 신규 6/6 — 처리 후 화면 캡처 `day18/after_정상회귀.png` (교재 이미지 정책상 저장소 제외, 로컬 보관)

## ⑤ 상호 점검 (옆 사람 역할)

수업 환경이 아니라 **Claude가 악의적 사용자 역할**로 대행 (자동 공격 스크립트) + 사장 직접 사용 점검. 외부인 점검 기회가 생기면 링크 교환 항목 추가 예정.

## 오늘의 교훈

1. **클라이언트 가드는 UX, 서버 제약이 방어** — maxlength는 프로그램적 호출을 못 막는다. 같은 규칙을 두 층에 두는 이유.
2. 공격은 자동화하면 재사용 가능한 자산이 된다 — `tests/day18-check.js`는 이후 모든 배포의 회귀 항목.
3. 배포 직후 CDN 캐시로 구버전이 서빙될 수 있다 — 검증은 새 버전 서빙 확인 후에.
