## 1. 페르소나별 검토 요약

### 💰 투자자 (초기 F&B 심사역) — 🟡 조건부 관망

**핵심 지적: "4대 숫자가 비어 있다"**

| 잘된 점 | 치명적 허점 |
|---|---|
| 가설/사실 구분이 정직 ("(가정)"·"(확인 필요)" 표기) | ① **수요 규모 추정 전무** — 유동인구·전환율·목표 건수/일 없음 |
| 검증 계획(R1 Q4)이 실행 항목으로 존재 | ② **노쇼 리스크 무대응** — 선결제 없는 예약, 완성된 드립·스콘 폐기 구조 |
| 타깃을 좁힌 결정 | ③ **캐파 미검토** — 핸드드립 1잔 3~4분(가정), 아침 1시간 처리량 = 매출 상한 |
| | ④ **가격 지불의사 미검증** — 5,500원 vs 아침 스피드 소비 |

- "이른 아침+품질+픽업"은 **해자가 아니라 위생요인** — 기술 장벽 0, 프랜차이즈 복제 용이. 실질 해자는 핸드드립 품질·단골 관계(확장 느림).
- 아침 픽업은 매출 엔진이 아닌 **유입 장치** — 종일 매출 모델과 결합한 손익 추정 필요.

### 🔧 CTO (기술·운영) — 기술 🟢 / 운영 🔴

**한 줄: "만들 수 있으나, 운영할 수 있는지는 아직 설계되지 않았다."**

- **기술 🟢**: 4주·결제 제외 범위로 충분히 실현 가능. 서버 없이 정적 페이지+외부 폼(→시트·이메일 알림)이 적정. 과잉 엔지니어링 금지.
- **운영 🔴**: 문서 전체가 "고객이 원하는가"만 다루고 **사장 1인의 접수 부하를 다루지 않음**:
  - 아침 피크에 드립 내리느라 폼 확인 불가 → 알림·확정 응답 흐름 미정
  - 스콘 매진 시 폼이 계속 예약받는 문제 (재고 개념 없음)
  - 월요일 휴무인데 폼이 요일을 안 막으면 휴무일 예약 유입
  - 픽업 시간 슬롯·동시 접수 한도 미정 (드립 처리량 = 병목)
- **데이터 최소 수집**: 호명용 이름+시간+메뉴면 충분. 연락처는 선택 입력 권장(필수화 = 전환율 하락).
- Day3 데모(새로고침 소실)와 실제 예약 오픈은 반드시 분리 — 영속화(Day4) 전 실고객 예약 금지.

### 🏛️ 허가기관 (마포구청 위생과 관점) — 🟢

**결제 제외 '예약 접수' 범위는 규제 부담이 사실상 없음. 단 1가지는 필수.**

- 결제 없는 웹 폼 예약 = 전화 예약과 실질 동일 → **통신판매업 신고 대상으로 보기 어려움** *(정확한 요건은 관할 기관·법령 원문 확인 필요)*. 결제를 범위에서 뺀 것은 규제 측면에서 합리적.
- **필수**: 폼에 **개인정보 수집 동의**(항목·목적·보유기간 명시) — 배포 전 반드시 삽입.
- 흔한 실수 경고: 동의 없이 폼만 부착 / 연락처의 홍보 무단 사용(별도 마케팅 동의 필요) / 구글시트 링크 공유로 개인정보 노출.
- 표시·광고: "당일 구운"·"직접 내린" 등은 실운영과 일치해야 함. 게시 가격 = 실제 결제 가격 유지.
- 향후 온라인 결제 도입 시(범위 밖) 통신판매업 신고 등 별도 검토 필요.

### 👥 고객 패널 5인 (가상 시뮬레이션) — 🟡

| 페르소나 | 사용 의향 | 결정 요인 |
|---|---|---|
| P1. 32세 출근 직장인 | ✅ 쓴다 | 픽업 시간 정확도. "예약했는데 안 됐어요" 한 번이면 끝 |
| P2. 58세 동네 주민 | ❌ 안 쓴다 | 폼 자체가 장벽. 시간에 안 쫓김. 5,500원 비싸게 느낌 |
| P3. 27세 프리랜서 | ❌ 안 맞음 | 오후 좌석·원두 정보가 니즈. 픽업 폼은 타깃 아님 신호 |
| P4. 41세 맞벌이 부모 | 🟡 조건부 | 개념 완벽하나 "폼 3단계 넘으면 즉시 이탈". 가격 무관 |
| P5. 21세 대학생 | ❌ 안 쓴다 | 가성비(메가 1,500원 대비). SNS 발견성 부재 |

- **타깃(출근길 직장인) 선정은 방향이 맞음** — 불편을 실제 느끼고 가격 저항 낮은 유일한 그룹(P1·P4).
- 단, 이들의 진짜 관문은 "예약이 되냐"가 아니라 **"예약이 정확하고 빠르냐"**.
- 놓친 인사이트: ① 결제·픽업 정확도가 수용의 관문 ② 웹 폼 자체가 마찰(카톡 채널 가정 검증 필요) ③ 매일 반복 주문(재주문 편의) 설계 부재.

## 2. 교차 분석 — 4개 관점이 수렴/충돌하는 지점

### 🔴 전 관점 수렴 (최우선 — 3개 이상 관점이 동일 지적)

| # | 수렴 이슈 | 지적한 관점 |
|---|---|---|
| 1 | **노쇼·픽업 정확도** — 선결제 없는 예약의 폐기 비용, 픽업 지연 시 재방문 소멸 | 투자자·CTO·고객 |
| 2 | **아침 피크 캐파·접수 운영** — 드립 병목 + 사장 1인이 폼 확인 불가 | 투자자·CTO·(고객 P1 간접) |
| 3 | **수요·전환 숫자 부재** — 시뮬레이션이 아닌 실측 필요 | 투자자·고객·(R1 Q4와 일치) |

### 🟡 관점 간 충돌 (의사결정 필요)

- **"결제 제외" 결정의 양면성**: 허가기관은 **긍정**(통신판매 신고 회피, 규제 최소) ↔ 투자자·고객은 **부정적 측면 지적**(노쇼 방어 불가, 매장 재계산이 "줄 안 서기" 가치를 반감). → 4주 범위에서는 결제 제외 유지가 타당하되, **노쇼·재계산 완화책**(픽업 시간 슬롯제, 단골 우선, 도착 알림 등)을 폼 설계에 반영해야 함.
- **폼 항목의 긴장**: 연락처 필수(노쇼 연락용) ↔ 최소 수집·전환율(CTO)·폼 마찰(고객 P4). → 연락처는 받되 항목 수를 최소로, 동의 문구 필수(허가기관).

### ✅ 전 관점이 지지한 것

- 타깃을 "출근길 직장인" 하나로 좁힌 결정
- 가설/사실을 구분한 정직한 문서 태도
- 4주 범위에서 결제·앱을 뺀 단계적 접근

## 4. Day3 화면 설계에 즉시 반영할 액션 (우선순위순)

1. **개인정보 수집 동의 체크박스 + 목적·보유기간 문구** (허가기관 — 필수)
2. **폼 마찰 최소화**: 항목 최소·3단계 이내, 연락처는 노쇼 연락 목적 명시 (고객·CTO)
3. **픽업 시간 슬롯제**(5~10분 단위) + 예약 마감 리드타임 정의 (CTO·투자자·고객)
4. **월요일 휴무 차단** + 영업시간 내 슬롯만 노출 (CTO)
5. **재고 소진 대응 문구**("스콘은 당일 소진 시 대체/취소 안내") (CTO)
6. Day3 데모임을 명시하고 실고객 예약과 분리 (CTO)
