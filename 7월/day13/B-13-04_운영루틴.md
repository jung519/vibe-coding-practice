# B-13-04 — 운영 루틴 메모

> 관리번호: **B-13-04** (기초반 · 13일차) · 작성일: 2026-07-22
> 도구가 다 갖춰진 지금, "사장의 하루"에 예약 처리가 어디에 끼는가

## 매일 아침 (개점 전, 5분)

1. ☕ 슬랙 확인 — 밤사이 들어온 새 예약 알림 훑기 (Day 12 자동화)
2. 🔐 관리자 화면 로그인 (`/day1/admin.html`) — 오늘 날짜 탭에서 시간순 확인
3. ✅ 준비 가능한 예약 **접수 → 확정** 처리 (재료·슬롯 확인 후)
4. 📝 요청사항(연하게 등) 메모해서 바 옆에

## 영업 중 (픽업 시간대 08:00~10:00)

- 손님 픽업 완료 시 → 해당 카드 **확정 → 픽업완료** (완료 항목으로 이동)
- 새 예약은 슬랙 알림으로 인지 → 새로고침 버튼으로 목록 갱신
- 노쇼(픽업 시간 +20분): 전화 1회 → 연결 안 되면 **취소** 처리

## 매주 월요일 (휴무일, 10분)

- 지난주 예약 흐름 훑기 — 몰리는 시간대·인기 메뉴 확인 (Day 14 Umami 측정과 연결 예정)
- **1개월 경과 예약 파기**: Table Editor에서 `created_at` 기준 필터 → 삭제 (개인정보 보유 정책 — B-02 PRD)
- Supabase 무료 플랜 활동 유지 확인 (7일 미사용 정지 — 평일 사용으로 자연 충족)

## 이상 징후 대응

| 증상 | 확인 | 조치 |
|---|---|---|
| 슬랙 알림이 안 옴 | SQL: `select status_code from net._http_response order by id desc limit 5` | Webhook URL 재발급 → `notify_slack()` 교체 |
| 관리 화면 로그인 실패 | 비밀번호 확인 | 대시보드 → Users → 비밀번호 재설정 |
| 예약이 안 들어옴 | 공개 URL 폼 제출 테스트 | Vercel 배포 상태·Supabase 프로젝트 상태 확인 |

## 도구 지도 (오늘 기준 전체 그림)

```
고객: 공개 URL 폼 (예약·내 예약 확인·취소)
  ↓ Supabase (진실: 규칙·슬롯·상태)
사장: 슬랙(알림 인지) → 관리자 화면(확인·상태 처리) → Table Editor(파기·비상)
```
