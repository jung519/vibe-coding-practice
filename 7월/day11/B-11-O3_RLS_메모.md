## 한 문장 요약

**localStorage는 "이 브라우저에만" 저장되지만, Supabase는 "서버에" 저장되어 어느 기기에서 접속해도 같은 예약 현황을 보고 사장에게 접수가 전달된다.**

## RLS — 익명 키(publishable)로 되는 것 / 안 되는 것

| 동작 | 허용? | 이유 | 라이브 검증 |
|---|---|---|---|
| INSERT (예약 접수) | ✅ | 고객 접수 채널 — 오늘의 목적 | 5건 접수 성공 |
| SELECT (테이블 직접 조회) | ⛔ | 개인정보 공개 조회 차단 | `select=*` → **0행** (L11) |
| UPDATE / DELETE | ⛔ | 변조·삭제 차단 | 정책 없음 = 전부 거부 |
| 사장 확인 | 대시보드 로그인 | Table Editor에서 확인 (관리 화면은 Day 13) | 접수 5건 확인 |

**핵심 설계: "직접 SELECT ≠ 조회 기능."** 테이블은 잠그고, 정해진 답만 내주는 **RPC 창구**를 열었다:

| RPC 함수 | 반환 | 안전 근거 | 라이브 검증 |
|---|---|---|---|
| `slot_status(날짜)` | 시간별 잔 수만 | 개인정보 필드 0개 (L12) | 새 세션에서도 08:10 마감 표시 (L7) |
| `my_reservations(이름, 전화)` | 본인 예약만 | 이름+전화 둘 다 일치해야 반환 | 취소 반영 확인 (L8) |
| `cancel_reservation(id, 이름, 전화)` | 성공 여부 | 본인 일치 + '접수' 상태만 | 서버 상태 '취소'로 변경 (L8) |

## 서버가 강제하는 영업 규칙 (일관성 검토 5건의 반영 결과)

폼을 거치지 않은 직접 API 호출도 서버가 거절한다 — 클라이언트는 편의, **서버가 진실**:

| 규칙 | 수단 | 라이브 검증 |
|---|---|---|
| 전화 숫자 10~11자리 | check 제약 (+ 클라이언트 검증 정렬) | 9자리 클라 차단 (S3) |
| 픽업 08:00~10:00만 | check 제약 | 23:00 직접 시도 → HTTP 400 (L9) |
| 월요일 휴무 | check 제약 (`dow <> 1`) | 2026-07-27(월) 직접 시도 → HTTP 400 |
| 슬롯당 3잔 (전 고객 합산) | INSERT 트리거 + 잠금 (SLOT_FULL) | 4잔째 직접 시도 → HTTP 400 (L3) |
