# B-12-O1 — 예약 알림 자동화 흐름

> 관리번호: **B-12-O1** (기초반 · 12일차 · 산출물 1) · 작성일: 2026-07-21
> 목표: 폼 한 번 제출에 알림이 또렷하게 도착한다 — 달성 ✅ (실검증 2026-07-21)

## 최종 흐름 (운영 중)

```
고객 폼 제출 (Vercel 페이지)
  → Supabase INSERT (reservations — RLS·check·슬롯 트리거 통과)
  → AFTER INSERT 트리거 notify_slack_on_insert
  → pg_net 비동기 POST (접수 응답을 막지 않음)
  → Slack Incoming Webhook
  → #채널 알림 도착 (사장 확인)
```

- **트리거 = 서버(진실) 시점**: 폼을 거치지 않은 직접 API 접수도 알림이 울린다. 클라이언트 발화 방식(웹훅 URL 노출·유실 위험)은 검토 후 배제.
- **비동기(pg_net)**: Slack이 느리거나 죽어도 고객 접수는 지연·실패하지 않는다.
- 설정 원본: `day12/setup.sql` (웹훅 URL은 플레이스홀더 — 실값은 DB 안에만 존재)

## 채널·도구 결정 기록

| 결정 | 내용 | 근거 |
|---|---|---|
| 채널 | **Slack** (교재 기본은 텔레그램/Gmail) | 사장 선택 — 의도된 편차. OAuth 연결이라 Bot Token 관리 불필요 |
| 도구 | **Zapier → Supabase 직결(pg_net)로 전환** | Zapier Webhooks는 프리미엄 앱 — 계정 trial(14일)이 이미 만료되어 Publish 불가. 직결은 영구 무료·서드파티 없음 |

### 시도한 Zapier 경로 (학습 기록 — Catch Hook 체험 완료)

```
Supabase Database Webhook → Zapier Catch Hook(트리거 테스트까지 성공) → Slack 액션 → Publish ❌ (trial 만료)
```

Catch Hook URL 발급·검증 POST·트리거 테스트(샘플 매핑)까지 진행했으므로 교재의 학습 포인트(트리거→액션, Catch Hook 연결)는 경험함. 전환 상세는 B-12-O4.

## 보안 메모

- Slack Incoming Webhook URL은 **비밀값** (아는 사람은 채널에 아무 메시지나 쏠 수 있음) — 저장소·프론트엔드에 올리지 않고 DB 함수 안에만 둠. 노출 시 Slack 앱 설정에서 재발급.
- Zapier에 service_role key 불필요했음(웹훅 push 구조) — 교재 보안 원칙과 일치.

## 확장 후보 (Day 13+)

- **취소 알림**: 고객 취소는 `cancel_reservation` RPC의 UPDATE — `AFTER UPDATE ... WHEN (new.status = '취소')` 트리거로 동일 패턴 확장 가능.
- 전송 실패 대응: pg_net은 재시도 없음 — 실패 로그(`net._http_response`) 주기 점검 또는 Edge Function 전환.
