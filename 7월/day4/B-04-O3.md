## 배포 과정 중 발견·해결한 문제 (기록)

1. **루트 404**: 저장소 루트에 index.html이 없어 `/` 접속 시 404 → **일차별 산출물 허브 페이지**를 루트에 추가해 해결. (`/day1/` 등 하위 경로는 처음부터 정상)
2. **URL 혼동**: `vibe-coding-practice.vercel.app`은 타인이 선점한 도메인(전혀 다른 사이트) — 실제 배정 주소는 `-xi` 접미사가 붙은 위 URL. `*.vercel.app` 이름은 전 세계 공용 네임스페이스임을 확인.

## 실서버 동작 검증 (Playwright, 배포 URL 대상)

`tests/day4-check.js`를 배포 URL로 실행 — **12항목 전부 통과**:

- 빈 상태 안내 / 픽업 날짜(월요일 휴무 제외) / [C] 생성(confirm→저장→완료 피드백)
- **localStorage 확정 JSON 구조** (version·bk_ id·status·타임스탬프 3종) 실측 일치
- **[R] 새로고침 후 예약 유지 (영속성 — 오늘의 핵심)** ✅
- [U] 상태 변경 + updatedAt 갱신 + 새로고침 유지 / [D] 삭제 + 새로고침 유지
- 슬롯 상한(3잔)·취소 시 반납·삭제 잠금 / 375px 겹침 없음

## 오늘의 핵심 개념 재확인 (교재)

배포 URL에서도 localStorage는 **접속한 각 브라우저에만** 저장된다 — 손님 폰의 예약이 사장 PC로 모이지 않고, 서버로도 전송되지 않는다. 실서버 테스트에서 넣은 데이터도 해당 테스트 브라우저에만 존재했다가 정리됨. **그래서 공개 URL이지만 실습용 가짜 데이터만 사용**하며, 진짜 수집(서버 저장)은 이후 과정(Supabase)에서 다룬다.
