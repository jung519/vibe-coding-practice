## 확인 방법

Chrome **DevTools(Cmd+Option+I) → Application 탭 → Storage → Local Storage → `https://vibe-coding-practice-xi.vercel.app`** 에서 Key `morningbrew.bookings` 선택 → 하단 트리에서 JSON 값 확인.

## 캡처에서 확인된 사실 (실측)

| 확인 항목 | 캡처 근거 |
|---|---|
| 저장 위치 | Local Storage, 오리진 `https://vibe-coding-practice-xi.vercel.app` |
| Key | `morningbrew.bookings` ✅ (확정 구조의 키 그대로) |
| 최상위 구조 | `{version: 1, bookings: [...]}` ✅ |
| 예약 객체 필드 | `id: "bk_1783582255446"`(타임스탬프 기반), name, phone, `menu: "핸드드립 커피 (5,500원)"`, `qty: 1`, `pickupDate: "2026-07-10"`, `time: "08:00"`, note ✅ — 확정 JSON 12개 필드 전부 존재 |
| 상태 관리(U) | `status: "확정"` — 목록에서 상태를 변경한 결과가 저장소에 반영됨 |
| 타임스탬프 3종 | `consentAt` = `createdAt` (동의 시각 증빙), `updatedAt`(16:30:59)이 `createdAt`(16:30:55)보다 **늦음** → 상태 변경이 updatedAt을 갱신했다는 증거 |

## 디버깅 체험 요점

- 화면(예약 목록)이 아니라 **저장소의 JSON이 진실의 원천** — DevTools에서 값을 지우고 새로고침하면 목록도 빈 상태가 된다.
- 저장소는 **오리진(도메인) 단위**로 분리된다 — 로컬 파일로 열 때와 배포 URL로 열 때의 localStorage는 서로 다른 공간이다.
- 배포 URL에서도 값은 **이 브라우저에만** 저장된다(서버 전송 없음) — 교재의 핵심 주의사항 실증.

## 반성 노트

캡처 데이터에 실명·실번호로 보이는 값이 들어감 — 교재 지침("실습용 가짜 데이터만") 대로 다음부터는 김테스트/010-0000-0000 류만 사용. 해당 캡처는 공개 저장소에서 제외 처리함.
