# 16일차 — NLP 전처리와 Word Embedding 입문

### 정규표현식 (Regular Expression)
- 정의: 특정 규칙을 가진 문자열 집합을 표현하는 형식 언어. 파이썬 `re` 라이브러리로 사용
- 설명: 텍스트 정제(구두점 제거 등)에 활용. 메타문자 — `[ ]` 문자 클래스, `.` 임의 문자 하나, `*` 0회 이상, `+` 1회 이상, `?` 0 또는 1회, `{m,n}` 반복 횟수, `|` 또는, `^` 문자열 시작, `\d` 숫자, `\s` 공백, `\w` 알파벳·숫자·언더바
- 시험 포인트: 함수 구분 — **match(맨 앞만) / search(전체 검색, 최다 사용) / findall(전부 리스트로) / sub(치환 — 구두점 제거용)**

### Stopwords (불용어)
- 정의: the, is처럼 의미 전달에 중요하지 않은 단어들 — 전처리에서 제거 대상
- 시험 포인트: NLTK 영어 불용어 리스트 약 179개. 제거 여부는 목적에 따라 선택

### Stemming (어간 추출)
- 정의: 단어의 어미를 **기계적으로 잘라** 같은 어근으로 통일하는 작업
- 설명: 빠르지만 거칠어서 사전에 없는 단어가 나올 수 있음 (crazy → crazi). 종류 — **Porter**(표준, 가장 많이 사용), Snowball(Porter 버전 2), Lancaster(과격, 정보 손실 주의), Regexp(규칙 직접 지정, 잘 안 씀)
- 시험 포인트: Lemmatization과의 구분이 출제 1순위

### Lemmatization (표제어 추출)
- 정의: 단어를 **사전상의 뿌리 형태**로 변환 (am/is/are → **be**)
- 설명: Stemming보다 정확하지만 **품사 정보를 함께 줘야** 제대로 동작
- 시험 포인트: **Stemming = 가위질(빠르고 거침) vs Lemmatization = 사전 찾기(정확, 품사 필요)**

### 형태소 분석기 / KoNLPy (코엔엘파이)
- 정의: 한국어를 형태소 단위로 분해하고 품사를 붙이는 도구. KoNLPy 패키지가 5종 제공 — Hannanum, Kkma, Komoran, MeCab(추가 설치 필요), **Okt**(구 Twitter)
- 설명: 한국어는 조사·어미가 붙어 띄어쓰기만으론 부족해서 필요. **Okt는 일상 대화체에 적합**하고 norm/stem 옵션으로 "되나욬ㅋㅋ"→"되다" 정규화 가능
- 시험 포인트: 공통 함수 3개 — **morphs(형태소 추출) / nouns(명사 추출) / pos(품사 태깅)**

### One-hot Encoding의 한계 (원핫 인코딩)
- 정의: 단어를 "자기 자리만 1, 나머지 0"인 벡터로 표현 (Sparse representation, 희소 표현)
- 설명: 치명적 한계 — **어떤 두 단어든 내적(유사도)이 항상 0**이고 **거리도 항상 √2로 동일** → 의미의 유사함을 표현할 수 없음
- 시험 포인트: "one-hot의 문제점은?" → 단어 간 유사도 표현 불가

### Dense / Distributed Representation (분산 표현)
- 정의: 단어의 의미를 여러 차원에 걸친 0이 아닌 값들로 표현한 벡터
- 설명: 이 표현에서는 거리·내적·코사인 유사도가 **실제 의미의 유사성을 반영** — 단어가 의미 공간의 좌표를 갖게 됨
- 시험 포인트: 희소(sparse) ↔ 밀집(dense)의 대비. 대표 학습법 = Word2Vec

### Word2Vec (워드투벡)
- 정의: 단어를 dense vector로 표현하는 대표적 word embedding 방법. **주변 단어(context) 정보로 학습**
- 설명: 이론적 근거 = **분포 가설** — "You shall know a word by the company it keeps"(단어의 의미는 함께 다니는 단어를 보면 안다, Firth 1957). "cat"의 의미 = cat 주변에 오는 단어들의 확률 분포
- 시험 포인트: 라벨 불필요(텍스트 자체가 정답) — self-supervised 계열

### Skip-gram (스킵그램)
- 정의: **중심 단어를 입력받아 주변 단어들을 예측**하도록 학습하는 Word2Vec 방식
- 설명: window 크기만큼 좌우 단어가 예측 대상. "a cute **cat** sits down"에서 cat → a, cute, sits, down 예측. 중심 단어 하나당 여러 학습 쌍 생성
- 시험 포인트: CBOW와 방향이 반대라는 것 (17일차 CBOW 항목 참조)

### BertTokenizer / ## / OOV (복습 — 15일차 이론의 실습)
- 정의: BERT의 subword 토크나이저(WordPiece 방식). **`##` = 단어 내부에서 이어지는 조각** (Tokenizer → To + ##ken + ##izer)
- 설명: 실습 비교 결과 — 철자(단어장 작음·문장 너무 김) / 단어(짧지만 **OOV** 문제·임베딩 폭증) / **subword(모든 축에서 균형 → 표준)**
- 시험 포인트: encode 시 문장 앞뒤에 **[CLS], [SEP] 자동 부착**

# 17일차 — Word2Vec 심화와 BERT

### Word2Vec의 내부 구조
- 정의: 행렬 두 장짜리 신경망 — y = softmax(행렬2 × 행렬1 × one-hot입력)
- 설명: **행렬1의 열과 행렬2의 행이 곧 각 단어의 임베딩.** 함께 등장하는 단어끼리 내적이 커지도록 학습 (drink 벡터 ↔ juice·milk·water 벡터)
- 시험 포인트: one-hot 입력에 행렬을 곱하는 것 = 해당 단어의 열을 뽑는 것과 동일

### CBOW (씨보우)
- 정의: **주변 단어들을 입력받아 중심 단어를 예측**하는 Word2Vec 방식
- 시험 포인트: **CBOW = 주변→중심 / Skip-gram = 중심→주변** (방향 반대 — 구분 문제 단골)

### 벡터 산술 / Analogy (유추)
- 정의: 학습된 임베딩에서 의미 관계가 벡터의 방향이 되는 성질
- 설명: **vec[queen] − vec[king] = vec[woman] − vec[man]** (성별 축). 유추 검색: **"한국 − 서울 + 도쿄 = 일본"**, woman + king − man → **queen**
- 시험 포인트: 15일차 DCGAN의 얼굴 벡터 산술과 같은 현상의 언어판

### Word Intrusion Detection (침입 단어 탐지)
- 정의: 단어 무리에서 의미상 이질적인 단어를 임베딩 유사도로 찾는 활용 예 ({hammer, saw, drill, **staple**})

### nn.Embedding (임베딩 층)
- 정의: 단어 번호(정수) → 벡터를 돌려주는 **학습되는 조회(lookup) 테이블**
- 시험 포인트: Transformer 실습(12일차)의 Embedding layer와 같은 것

### GloVe / 사전학습 임베딩
- 정의: 대규모 코퍼스(위키백과 등)로 미리 학습해 둔 word embedding
- 설명: 실습 교훈 — 문서 한 편으로 직접 학습하면 유사 단어가 엉망, 사전학습 임베딩은 freedom → freedoms, liberty, democracy로 정확. **임베딩 품질 = 데이터 양**
- 시험 포인트: PCA로 2차원 시각화하면 의미 범주별로 군집

### Self-supervised Learning (자기 지도 학습)
- 정의: **데이터의 일부를 가리고 그 부분을 예측**하도록 학습 — 라벨 불필요
- 설명: 예시 — 이미지 인페인팅, 직소 퍼즐, Word2Vec, 그리고 BERT의 MLM
- 시험 포인트: Pretraining(사전학습)의 표준 방법

### Transfer Learning / Pretraining / Fine-tuning (전이 학습)
- 정의: Pretraining = 대규모 데이터로 사전학습 / Fine-tuning = 사전학습 모델을 목표 태스크(target/downstream/fine-tuning task)에 맞춰 추가 학습
- 시험 포인트: 사전학습 모델의 뒷부분을 태스크용 모듈로 교체하고 재학습

### BERT (버트)
- 정의: **B**idirectional **E**ncoder **R**epresentations from **T**ransformers — Transformer **인코더만** 크게 쌓은 사전학습 모델
- 설명: 양방향(문장 전체를 앞뒤로 다 봄) = "이해 전문가". 크기 — **Base: 12층·768차원·12헤드 / Large: 24층·1024차원·16헤드**. 토크나이저는 **WordPiece**
- 시험 포인트: 사전학습 과제 2개 = MLM + NSP (아래). GLUE 벤치마크 당시 1위, SQuAD(독해)에서 사람 점수 초과

### MLM (Masked Language Modeling, 마스크드 랭귀지 모델링)
- 정의: 입력 토큰의 **15%를 가리고 맞추게** 하는 BERT 사전학습 과제 (빈칸 채우기)
- 설명: 15% 중 **80%는 [MASK] 토큰으로, 10%는 무작위 다른 토큰으로, 10%는 그대로** — 이유: 실전 문장엔 [MASK]가 없으므로 거기에만 익숙해지면 안 되고, 항상 바꾸면 편향 발생
- 시험 포인트: **15% / 80·10·10 숫자와 그 이유**가 최다 출제 후보

### NSP (Next Sentence Prediction)
- 정의: 문장 A 뒤에 문장 B가 **실제로 이어지는 문장인지** IsNext/NotNext로 맞추는 BERT 사전학습 과제

### BERT의 입력 임베딩 (Token + Segment + Position)
- 정의: 토큰마다 **세 임베딩의 합** — Token(WordPiece) + **Segment(문장 A/B 구분)** + Position(BERT는 **학습형**)
- 시험 포인트: "BERT 입력을 구성하는 세 가지 임베딩은?" 유형

### [CLS] / [SEP] (특수 토큰)
- 정의: [CLS] = 문장 전체를 대표하는 분류용 토큰(맨 앞) / [SEP] = 문장 구분 토큰
- 시험 포인트: **fine-tuning 매칭 — 문장(쌍) 분류 → [CLS] 출력 사용 / 토큰 태깅(개체명 인식) → 각 토큰의 출력 사용 / 기계 독해(MRC, SQuAD) → 지문에서 정답의 시작·끝 위치 예측**

# 18일차 — GPT, BART/T5, HuggingFace

### GPT (Generative Pretrained Transformer)
- 정의: Transformer **디코더만**(masked self-attention) 쌓고, **language modeling(다음 단어 예측)** 하나로만 사전학습한 모델
- 설명: 출력을 다음 입력으로 되먹이며 한 토큰씩 생성(**autoregressive**). GPT-1→2→3 모두 구조·학습 방식 동일, **데이터와 크기만 증가**
- 시험 포인트: BERT(인코더·이해)와의 대비 — GPT는 디코더·생성

### GPT-1 / GPT-2 / GPT-3 (세대 구분)
- **GPT-1** (12층): 사전학습 후 **태스크별 linear layer를 붙여 fine-tuning** (고전적 전이 학습)
- **GPT-2** (15억 파라미터): 40GB 양질 데이터 — 커뮤니티 댓글 중 **좋아요 3개 이상 받은 글의 외부 링크**에서 수집. **Zero-shot** 능력 등장 (fine-tuning 없이 "in French" 붙이면 번역, "in summary" 붙이면 요약)
- **GPT-3** (**1,750억** 파라미터): 너무 커서 fine-tuning 사실상 불가 → **In-context learning**으로 활용. 클수록 성능이 계속 향상(포화 없음)
- 시험 포인트: 세대별 "활용 방식"의 구분 (fine-tuning → zero-shot → in-context)

### Zero-shot / One-shot / Few-shot (샷 구분)
- 정의: 프롬프트에 넣는 **예시 개수**에 따른 구분 — Zero(설명만) / One(예시 1개) / Few(예시 여러 개)
- 시험 포인트: **예시가 많을수록, 모델이 클수록 성능↑** (특히 큰 모델일수록 few-shot 효과가 가파름)

### In-context Learning (인컨텍스트 러닝)
- 정의: 프롬프트에 태스크 설명과 예시를 넣으면 **파라미터 수정(gradient 학습) 없이** 문맥만으로 태스크를 수행하는 GPT-3의 능력
- 설명: 모델에 입력하는 전체 텍스트 = **Prompt(프롬프트)**. 프롬프트 구성(예시 순서, 문장 길이, 질문 형태)에 따라 성능이 크게 달라짐 → 최적 구성을 찾는 과정 = **프롬프트 튜닝**
- 시험 포인트: "파인튜닝 없이 예시로 태스크를 수행하는 방법은?" → In-context learning

### Copilot / HyperCLOVA (응용 사례)
- 정의: Copilot = GitHub의 코드 자동완성(코드로 학습한 GPT 계열, OpenAI Codex) / HyperCLOVA = 네이버의 한국어판 GPT-3

### Transformer 3가문 (구조별 사전학습 모델)
- 정의: **인코더만 = BERT(이해: 분류·태깅)** / **디코더만 = GPT(생성: language modeling)** / **인코더-디코더 = BART·T5(변환: 번역·요약)**
- 시험 포인트: 구조-대표모델-용도 매칭 문제로 나오기 최적

### BART (바트)
- 정의: **B**idirectional and **A**uto-**R**egressive **T**ransformer — 인코더-디코더 구조 사전학습 모델
- 설명: 사전학습 = 문장을 **망가뜨려서**(토큰 마스킹, **문장 순서 섞기**) 인코더에 넣고 디코더가 **원문을 복원 생성**. 분류에 쓸 땐 디코더 **마지막 토큰의 출력** 사용
- 시험 포인트: 이해 성능 유지 + **요약에서 최고 성능**

### T5 (티파이브)
- 정의: **T**ext-**t**o-**T**ext **T**ransfer **T**ransformer — **모든 NLP 태스크를 "텍스트 입력 → 텍스트 출력"으로 통일**한 모델
- 설명: 입력 앞에 태스크 접두어(prefix)를 붙임 — "translate English to German: ...", "summarize: ...". 유사도 점수(3.8)도 텍스트로 출력
- 시험 포인트: 체계적 비교 실험의 결론 — **구조는 인코더-디코더, 사전학습은 replace span 방식**(문구 단위로 가리고 가린 부분만 생성) **채택**

### HuggingFace (허깅페이스)
- 정의: 사전학습 모델을 공유·활용하는 생태계(모델 허브 + 라이브러리)
- 설명: `AutoTokenizer.from_pretrained(...)` / `AutoModelForSequenceClassification.from_pretrained(...)`로 모델·토크나이저 자동 로드. 공식 모델과 사용자 업로드 모델 모두 제공
- 시험 포인트: **특수 토큰 추가(add_special_tokens) 후엔 반드시 model.resize_token_embeddings(len(tokenizer)) 호출** — "주의!" 포인트

### Trainer / TrainingArguments (트레이너 API)
- 정의: 학습·평가·추론 루프를 대신 돌려주는 HuggingFace API
- 설명: **TrainingArguments**(epoch, batch_size 등 설정) + **compute_metrics**(평가 지표 함수) + **Trainer**(모델·데이터 전달) → `.train()` 호출로 학습, `trainer.predict()`로 추론
- 시험 포인트: 5일차의 학습 루프(zero_grad→forward→loss→backward→step)가 이 안에 들어 있음

### 토크나이저 비교 / KLUE-BERT (클루버트)
- 정의: 언어별 토크나이저 성능 차이 — BERT(영어 우수, 한국어 부적합) / **KLUE-BERT**(한국어 우수) / mBERT(둘 다 지원하나 한국어 단일 태스크는 KLUE-BERT 권장)
- 시험 포인트: **한국어 태스크엔 한국어 특화 토크나이저**. tokenizer_fast(Rust 기반)가 기본값으로 대용량에서 최대 20배 빠름

# 19일차 — Decoding 전략과 생성 평가

### Decoding (디코딩)
- 정의: 언어 모델이 만든 "다음 단어 확률 분포"에서 **실제로 단어를 골라 문장을 만드는** 과정
- 설명: 전체 문장 확률이 최대인 문장을 완전 탐색으로 찾는 건 불가능(어휘 수^길이 개) → autoregressive하게 한 단어씩 선택
- 시험 포인트: 전략에 따라 같은 모델도 완전히 다른 문장을 생성

### Greedy Decoding (그리디 디코딩)
- 정의: 매 time step마다 **확률 1등 단어만** 선택하는 방식
- 설명: 빠르지만 근시안적 — 지금의 최선이 전체 문장의 최선을 보장하지 않음. 최적해의 근사일 뿐
- 시험 포인트: 반복(degeneration)에 취약. temperature→0과 동일한 결과

### Beam Search (빔 서치) / Beam size
- 정의: 매 time step마다 **후보 k개(beam size)를 유지**하며 탐색하는 방식
- 설명: 각 후보를 k개씩 확장(k²개) 후 점수 상위 k개만 유지. 점수 = 로그 확률의 누적 합(음수, 클수록 좋음). 슬라이드 예시: k=2로 "he hit me with a pie" 생성
- 시험 포인트: **긴 문장이 불리해지므로 문장 길이로 나눠 보정**(길이 정규화). 한계 = 확률 높은 것만 골라 **반복에 취약**, 다양성 부족

### Degeneration (퇴화, 반복 생성)
- 정의: 같은 구절이 무한 반복되는 생성 실패 현상
- 설명: 사람은 확률 낮은 단어도 수시로 쓰는데(그래프 비교), 확률 높은 것만 고르면 로봇 같은 반복문이 됨
- 시험 포인트: Greedy/Beam search의 문제 → Sampling 도입의 이유

### Sampling (샘플링)
- 정의: 확률 분포에 따라 **추첨**으로 단어를 선택 — 낮은 확률 단어에도 기회
- 설명: 출력이 비결정적이 됨 (같은 입력에 매번 다른 문장)
- 시험 포인트: "출력이 deterministic하지 않게 된다"는 표현

### Temperature (온도, τ)
- 정의: softmax에 나누기로 들어가 **분포의 뾰족함을 조절**하는 값
- 설명: **τ > 1 = 분포 평평 → 다양성 증가** (τ→∞면 uniform = 의미 없는 글) / **τ < 1 = 분포 뾰족 → 정확성 증가** (τ→0이면 one-hot = **greedy와 동일**)
- 시험 포인트: 방향 헷갈리지 말 것 — 높으면 다양, 낮으면 정확

### Top-k Sampling (톱케이 샘플링)
- 정의: 확률 상위 **k개 단어만** 후보로 남기고 그 안에서 추첨
- 설명: 단점 — k가 고정이라 분포 모양에 적응 못 함 (평평한 분포에선 비슷한 후보가 잘리고, 뾰족한 분포에선 확률 낮은 후보까지 포함)
- 시험 포인트: Top-p와의 차이(고정 vs 적응)가 출제 1순위

### Top-p Sampling (톱피 샘플링, Nucleus sampling)
- 정의: 확률 **누적 합이 p가 될 때까지** 후보를 포함하고 그 안에서 추첨
- 설명: 분포가 평평하면 후보 많이, 뾰족하면 적게 — **분포 모양에 자동 적응** (Top-k의 단점 해결)
- 시험 포인트: 별명 **Nucleus sampling**. "누적 확률"이라는 단어가 열쇠

### Perplexity (퍼플렉시티, PPL)
- 정의: 언어 모델이 다음 단어를 고를 때 **평균 몇 개의 선택지를 고민하는가**를 나타내는 평가 지표
- 설명: Perplexity = 2^(cross entropy loss). 정답 확률이 1/4이면 PPL 4 = "4개 중에 고민". **낮을수록 좋음**
- 시험 포인트: cross entropy와의 관계식. GPT-2가 클수록 PPL 하락(성능 향상)

### Precision / Recall (문장 비교에서)
- 정의: Precision = 예측 문장의 단어 중 정답 문장에도 있는 비율 / Recall = 정답 문장의 단어 중 예측에도 있는 비율
- 설명: 함정 2개 — ① 같은 단어 반복("the the the...")으로 만점 → 정답 등장 횟수로 **상한(clip, min 함수)** ② **어순 무시** ("the lazy dog jumps..."처럼 순서만 섞은 문장이 만점) → n-gram으로 해결
- 시험 포인트: 7일차 분류 평가의 precision/recall과 같은 개념의 문장 버전

### N-gram (엔그램)
- 정의: **연속된 N개 단어를 한 묶음**으로 취급하는 단위 ("I go to school"의 2-gram = (I,go), (go,to), (to,school))
- 시험 포인트: 어순을 평가에 반영하는 도구

### BLEU (블루)
- 정의: 번역 평가 지표 — **1~4-gram precision의 기하평균 × 짧은 문장 벌점(brevity penalty)**
- 설명: 어순이 엉망이면 4-gram precision이 0이 되어 점수 붕괴 (예시: 단어만 같은 문장 BLEU 0%)
- 시험 포인트: **BLEU = Precision 계열 = 번역 평가**

### ROUGE (루즈)
- 정의: 요약 평가 지표 — **n-gram recall** 기준
- 설명: "나와야 할 내용이 빠지지 않았는가"를 재므로 요약(Summarization)에 적합
- 시험 포인트: **ROUGE = Recall 계열 = 요약 평가** (BLEU와 세트로 구분 암기)

### LM Head (엘엠 헤드)
- 정의: Transformer 출력 벡터를 **어휘 크기만큼의 점수**로 바꾸는 마지막 선형 층
- 시험 포인트: 언어 모델의 출력 구조(각 위치마다 어휘 전체에 대한 점수)

### DistilGPT-2 / mBART (실습 모델)
- 정의: DistilGPT-2 = GPT-2 소형판(6층, 8,200만 파라미터, 어휘 5만) / mBART = 50개 언어 지원 BART(4억 파라미터, 어휘 25만)
- 설명: mBART 번역 = 인코더에 원문, 디코더 시작 토큰을 **목표 언어 토큰**으로 지정. 클래스는 AutoModelForSeq2SeqLM(인코더-디코더용)
- 시험 포인트: 실습 교훈 — **생성 모델은 팩트체킹 능력이 없음**(그럴듯한 오답을 자신 있게 생성 = 할루시네이션). GPT-2의 패딩 토큰은 EOS 토큰으로 설정
